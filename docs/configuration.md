# Конфигурация

Этот документ является единым справочником по переменным окружения проекта. `.env.example` намеренно содержит только минимальные значения для быстрого запуска; остальные настройки задаются через `docker-compose.yml`, `litellm-config.yaml`, административный интерфейс LiteLLM, параметры Makefile или переменные окружения конкретных быстрых проверок.

Правило эксплуатации: секреты и локальные значения первичной настройки лежат в `.env`, публичные имена моделей, пользовательские ключи, бюджеты и доступы пользователей администрируются через административный интерфейс LiteLLM, а расширенные политики запуска меняются только осознанно и документируются в заявке на изменение.

## Пул GLM-провайдеров по умолчанию

| Переменная | Значение по умолчанию | Допустимые значения | На что влияет |
| --- | --- | --- | --- |
| `ZAI_API_KEY` | Обязательный секрет | Ключ Z.AI Coding Plan | Первый ключ провайдера для групп моделей `glm-5.2` и `glm-5.1` по умолчанию. Остается только на хосте прокси, клиентам не выдается. |
| `ZAI_API_KEY_2` | Обязательный секрет | Ключ Z.AI Coding Plan | Второй ключ провайдера для того же публичного имени модели. Нужен для пула провайдеров моделей и проверки закрепления маршрута за клиентским ключом. |

Оба ключа считаются обязательными даже для быстрого запуска: текущий `litellm-config.yaml` объединяет две подписки в одно публичное имя модели `glm-5.2`, а `glm-5.1` оставляет как дополнительное имя для установок, которым нужна предыдущая модель.

Идентификаторы моделей OpenAI/Anthropic в примере дополнительных провайдеров являются значениями-заполнителями. Перед промышленным включением их нужно проверить на текущем образе LiteLLM и конкретной подписке.

| `JWT_AUDIENCE` | Пусто | Строка `audience` | Ожидаемая `audience` для JWT/OIDC-аутентификации. |

## Экспериментальный пул ChatGPT OAuth-подписок codex-lb

Эти настройки используются только в составе `STACK=litellm-presidio-codex-lb`.
Обычный GLM-профиль от них не зависит. Администратор вручную создаёт пароль и
импортирует подписки через штатный интерфейс, после чего `make setup` включает
аутентификацию API и выпускает служебный ключ через официальный API `codex-lb`.
Полный порядок запуска, первичной настройки, резервного копирования и обновления:
[codex-lb.md](codex-lb.md).

| Переменная | Значение по умолчанию | Допустимые значения | На что влияет |
| --- | --- | --- | --- |
| `CODEX_LB_POSTGRES_PASSWORD` | Генерируется `make setup STACK=litellm-presidio-codex-lb` | Стойкая строка из латинских букв, цифр, `-` и `_` | Пароль отдельного PostgreSQL `codex-lb`. Входит во внутренний `CODEX_LB_DATABASE_URL`; вручную заданный пароль не перезаписывается. |
| `CODEX_LB_API_KEY` | `***` до первичной настройки | Служебный ключ вида `sk-clb-...` | `make setup STACK=litellm-presidio-codex-lb` создаёт или перевыпускает именованный ключ через штатный административный API, проверяет его и атомарно сохраняет в `.env`. Используется только LiteLLM для внутренних вызовов. |
| `CODEX_LB_PORT` | `2455` | TCP-порт хоста | Порт административного интерфейса и API. В корпоративном профиле его публикует общий Nginx, а не контейнер `codex-lb`. В `.env.example` не добавляется. |
| `CODEX_LB_METRICS_PORT` | `9090` | TCP-порт хоста | Необязательное переопределение опубликованного порта штатных метрик. В `.env.example` не добавляется. |
| `CODEX_LB_DATA_DIR` | `/var/lib/codex-lb` | Путь внутри контейнера | Внутренняя постоянная директория ключа шифрования и служебных данных. Зафиксирована в Compose и хранится в отдельном томе `codex-lb-data`; для восстановления нужна вместе с базой. |
| `CODEX_LB_DATABASE_URL` | Внутренний PostgreSQL URL | URL `postgresql+asyncpg://...` | Соединяет `codex-lb` с отдельным контейнером `codex-lb-db`; формируется Compose из фиксированных имени пользователя/БД и `CODEX_LB_POSTGRES_PASSWORD`. |
| `CODEX_LB_DASHBOARD_AUTH_MODE` | `standard` | `standard` в этом профиле | Включает штатную парольную защиту административного интерфейса. TOTP остаётся необязательной настройкой администратора. |
| `CODEX_LB_METRICS_ENABLED` | `true` | `true` в этом профиле | Включает штатный сервер метрик на внутреннем порту `9090`. |
| `CODEX_LB_TELEMETRY_ENABLED` | `false` | `false` в этом профиле | Запрещает внешнюю телеметрию `codex-lb` с первого запуска. |
| `CODEX_LB_HTTP_RESPONSES_SESSION_BRIDGE_ENABLED` | `true` | `true`, `false` | Разрешает `codex-lb` преобразовывать входящие HTTP-запросы Responses API в сеанс с постоянным соединением до ChatGPT. Установите `false`, если корпоративный прокси не пропускает WebSocket. Между LiteLLM и `codex-lb` по-прежнему используется HTTP. |
| `CODEX_LB_UPSTREAM_STREAM_TRANSPORT` | `auto` | `auto`, `http`, `websocket` | Выбирает транспорт от `codex-lb` до ChatGPT. Значение `http` принудительно использует HTTP/SSE и подходит для прокси без WebSocket; `auto` сохраняет штатный выбор платформы. |

## Изолированная корпоративная среда

Эти переменные используются в специализированных ветках для корпоративного
окружения. Пошаговая инструкция находится в [air-gapped.md](air-gapped.md).

| Переменная | Значение по умолчанию | Допустимые значения | На что влияет |
| --- | --- | --- | --- |
| `NGINX_HTTP_PORT` | `80` | TCP-порт | Порт общей точки входа LiteLLM. В объединённом профиле тот же Nginx публикует `codex-lb` через `CODEX_LB_PORT`. |
| `HTTP_PROXY` | Пусто | URL HTTP-прокси без встроенных секретов | Общий прокси для загрузок при сборке и исходящих HTTP-соединений LiteLLM и `codex-lb`. |
| `HTTPS_PROXY` | Пусто | URL HTTP-прокси с поддержкой CONNECT | Общий прокси для HTTPS-загрузок, вызовов провайдеров, OAuth и ChatGPT. |
| `NO_PROXY` | Имена локальных сервисов | Список узлов, доменов и подсетей через запятую | Исключает Analyzer, Redis, обе базы PostgreSQL, Nginx, LiteLLM и `codex-lb` из проксирования. |
| `PIP_INDEX_URL` | Пусто | URL простого индекса Python-пакетов | Внутреннее зеркало обычных зависимостей Analyzer и тестового образа защитного слоя. При пустом значении используется стандартный индекс pip. |
| `PIP_TRUSTED_HOST` | Пусто | Имя узла | Отключает проверку TLS только для указанного зеркала pip. Не задавать, если зеркало использует доверенный сертификат. |
| `PIP_PROXY` | Пусто | URL отдельного прокси без встроенных секретов | Переопределяет общий прокси только для pip. |
| `PYTORCH_INDEX_URL` | `https://download.pytorch.org/whl/cpu` | URL индекса с `torch==2.13.0+cpu` | Отдельный источник CPU-only PyTorch. В изолированной сети должен указывать на одобренное зеркало точной версии. |
| `NER_MODEL_PROXY` | Пусто | URL HTTP-прокси без встроенных секретов | Переопределяет общий прокси только для загрузки закрепленных файлов NER-модели во время сборки. |

Корпоративная цепочка сертификатов хранится локально в верхнеуровневых файлах
`certs/*.crt`; это не переменные окружения и не часть репозитория. Вся
директория передаётся в контекст сборки, поэтому её содержимое проверяет
оператор. В объединённом профиле цепочка добавляется также в системное и Python-
хранилища доверия `codex-lb`.

## Сервис Presidio Analyzer

| Переменная | Значение по умолчанию | Допустимые значения | На что влияет |
| --- | --- | --- | --- |
| `PRESIDIO_ANALYZER_URL` | `http://presidio-analyzer:5001` | HTTP-адрес | Маршрут Analyzer, в который защитный слой LiteLLM отправляет текст для детекции. |
| `PRESIDIO_ANALYZER_PORT` | `5001` | TCP-порт | Порт самостоятельного запуска `presidio/analyzer_server.py`; в Docker Compose порт фиксирован командой uvicorn. |
| `PRESIDIO_ANALYZER_WORKERS` | `1` | Положительное целое | Количество рабочих процессов uvicorn. Каждый процесс загружает отдельную копию spaCy и BERT-модели, поэтому память растет примерно линейно. |
| `PRESIDIO_ANALYZER_CONCURRENCY_LIMIT` | `1` | Положительное целое | Максимум активных запросов Analyzer внутри одного рабочего процесса. |
| `PRESIDIO_ANALYZER_QUEUE_LIMIT` | `8` | Ноль или положительное целое | Размер очереди ожидания свободного места для анализа. |
| `PRESIDIO_ANALYZER_QUEUE_TIMEOUT_SECONDS` | `0.25` | Положительное число | Сколько ждать свободное место перед `503 analyzer_overloaded`. |

Эффективная параллельность Analyzer: `replicas * PRESIDIO_ANALYZER_WORKERS * PRESIDIO_ANALYZER_CONCURRENCY_LIMIT`. Перегрузка Analyzer всегда трактуется защитным слоем как безопасный отказ независимо от `PII_GUARDRAIL_FAILURE_MODE`.

## Калибровка распознавателей

| Переменная | Значение по умолчанию | Допустимые значения | На что влияет |
| --- | --- | --- | --- |
| `PRESIDIO_ANALYZER_DETECT_BARE_INN_BY_CHECKSUM` | `true` | `true`, `false` | При `true` 12-значный ИНН с корректной контрольной суммой проходит `score_threshold=0.35` даже без контекста; 10-значный ИНН всё равно требует контекст. При `false` любой ИНН без контекста не проходит порог. |
| `PRESIDIO_ANALYZER_INTERNAL_DOMAIN_SUFFIXES` | `internal,local,lan,corp,corp.local,cluster.local,svc.cluster.local` | Список суффиксов через запятую или пробел | Какие доменные суффиксы распознаватель `INTERNAL_DOMAIN` считает внутренними. |
| `PRESIDIO_ANALYZER_DETECT_PUBLIC_IPS` | `true` | `true`, `false` | При `true` `INTERNAL_IP` распознаёт все корректные IPv4- и IPv6-адреса. При `false` остаются только приватные и внутренние диапазоны. |

## Политики защитного слоя

| Переменная | Значение по умолчанию | Допустимые значения | На что влияет |
| --- | --- | --- | --- |
| `PII_GUARDRAIL_MODE` | `mask` | `mask`, `block` | Штатное поведение при найденных персональных данных: обратимое маскирование или блокировка запроса до вызова провайдера. |
| `PII_GUARDRAIL_FAILURE_MODE` | `fail_closed` | `fail_closed`, `fail_open` | Поведение при обычных инфраструктурных сбоях Analyzer/Redis. `fail_closed` останавливает запрос, `fail_open` пропускает его дальше. Перегрузка Analyzer и недоступность обязательной NER-модели всегда приводят к безопасному отказу независимо от этой настройки. |
| `PII_MAPPING_TTL_SECONDS` | `3600` | Положительное целое | Время жизни Redis-сопоставления `pii_mapping:<pii_request_id>` для восстановления служебных меток в ответе. |
| `PRE_EGRESS_POLICY_MODE` | `block` | `block`, `off` | Проверка всей полезной нагрузки до Analyzer: блокирует выгрузки `.env`, kubeconfig/манифесты, конфигурации nginx, журналы доступа/аутентификации и трассировки ошибок. |
| `FINAL_PAYLOAD_LEAK_CHECK_MODE` | `block` | `block`, `off` | Финальная проверка без изменения полезной нагрузки после мутации и до вызова провайдера. |
| `FINAL_PAYLOAD_LEAK_CHECK_CANARIES` | Пусто | Токены через запятую или перевод строки | Детерминированные маркеры для быстрых и регрессионных проверок того, что исходный маркер не доходит до провайдера. Не используйте реальные секреты как контрольные маркеры. |

## Закреплённая модель NER

Analyzer использует только `fef2/ner_rus_bert-secret_detection` в ревизии `52b5b0745aac14f73fcf2ac0f91d9b5001a85ae4`. Идентификатор модели, ревизия, разрешённые файлы, размеры и SHA-256 записаны в `presidio/model_manifest.json`. Пользовательских переменных окружения для замены модели или отключения NER нет.

Модель скачивается и проверяется в отдельной стадии сборки, независимой от
Python-зависимостей. PyTorch устанавливается из официального процессорного
репозитория в точной версии `2.13.0+cpu`; CUDA и выполнение на видеокарте не
поддерживаются. Тестовая цель `analyzer-test` не содержит весов, а рабочая цель
`analyzer` не содержит `pytest`, компиляторов и `curl`.

Во время работы Transformers загружает модель только из
`/opt/models/ner_rus_bert-secret_detection` с отключённым сетевым поиском. Если
файлы отсутствуют, повреждены или не соответствуют ожидаемым меткам, Analyzer
не запускается. Источники, граница заимствования, проверка целостности и порядок
обновления описаны в
[документе о происхождении модели](research/ner-model-provenance.md).
