# Конфигурация

Этот документ является единым справочником по переменным окружения проекта. `.env.example` намеренно содержит только минимальные значения для быстрого запуска; остальные настройки задаются через `docker-compose.yml`, `litellm-config.yaml`, административный интерфейс LiteLLM, параметры Makefile или переменные окружения конкретных быстрых проверок.

Правило эксплуатации: секреты и локальные значения первичной настройки лежат в `.env`, публичные имена моделей, пользовательские ключи, бюджеты и доступы пользователей администрируются через административный интерфейс LiteLLM, а расширенные политики запуска меняются только осознанно и документируются в заявке на изменение.

## Локальные профили OpenAI OAuth

Экспериментальный пул из задачи #72 использует локальный файл
`config/openai-oauth/profiles.local.yaml`. Файл исключён из Git и описывает
только состав конкретной установки. Безопасный шаблон находится в
`config/openai-oauth/profiles.example.yaml`:

```yaml
schema_version: 1
models:
  - public_name: gpt-5.4
    provider_model: chatgpt/gpt-5.4
  - public_name: gpt-5.3-codex
    provider_model: chatgpt/gpt-5.3-codex
profiles:
  - id: subscription-a
    enabled: true
  - id: subscription-b
    enabled: true
```

`models` — общий набор публичных имён и моделей провайдера для всех подписок.
Указывайте здесь только модели, доступные во всех подключённых подписках. Общий
список исключает расхождение наборов между профилями. `public_name` не раскрывает
клиенту внутренний тип провайдера, а `provider_model` использует префикс
`chatgpt/`, который ожидает LiteLLM. `profiles` содержит только безопасный
идентификатор `id` и признак `enabled`; идентификатор ограничен 64 строчными
латинскими буквами, цифрами, `_` и `-` и должен начинаться с буквы или цифры.

OAuth-токены, `account_id`, электронная почта и произвольные пути в этот файл не
записываются. Файл авторизации каждого профиля будет находиться по однозначному
пути `secrets/openai-oauth/<profile-id>/auth.json`, который также исключён из
Git. На текущем этапе локальный файл ещё не подключён к Compose и не влияет на
работающий прокси; загрузка и проверка появятся в следующих шагах задачи #72.

Новые переменные окружения для списка профилей не вводятся.

Подготовленный в отдельном `CODEX_HOME` файл импортируется локально:

```bash
.venv/bin/python scripts/import_codex_auth.py \
  --profile-id subscription-a \
  --source /path/to/isolated/CODEX_HOME/auth.json
```

Импорт разрешён только для включённого профиля из локальной конфигурации. Скрипт
проверяет формат Codex, преобразует вложенные токены в формат LiteLLM и создаёт
`secrets/openai-oauth/<profile-id>/auth.json` с правами `0600` в каталоге с
правами `0700`. Исходный файл не изменяется. Токены, адрес электронной почты и
идентификатор аккаунта не выводятся. Без `--replace` существующий профиль не
перезаписывается.

Чтобы обновить истёкшую или отозванную сессию уже подключённого профиля, снова
подготовьте `auth.json` в отдельном `CODEX_HOME` и выполните:

```bash
.venv/bin/python scripts/import_codex_auth.py \
  --profile-id subscription-a \
  --source /path/to/isolated/CODEX_HOME/auth.json \
  --replace
```

Обновление разрешено только для того же `account_id`: привязать к существующему
профилю другой аккаунт нельзя. Активный файл профиля нельзя указывать как
источник. Скрипт сначала полностью проверяет новый файл, затем под общей с
LiteLLM блокировкой `.import.lock` атомарно заменяет `auth.json`; при ошибке
предыдущая сессия сохраняется. После подключения пула к LiteLLM работающие
процессы увидят новый файл без перезапуска, а параллельное обновление токена не
сможет вернуть старую сессию.

## Закреплённая модель NER

Analyzer использует только `fef2/ner_rus_bert-secret_detection` в ревизии `52b5b0745aac14f73fcf2ac0f91d9b5001a85ae4`. Идентификатор модели, ревизия, разрешённые файлы, размеры и SHA-256 записаны в `presidio/model_manifest.json`. Пользовательских переменных окружения для замены модели или отключения NER нет.

Модель скачивается и проверяется в отдельной стадии сборки, независимой от
Python-зависимостей. PyTorch устанавливается из официального процессорного
репозитория в точной версии `2.13.0+cpu`; CUDA и выполнение на видеокарте не
поддерживаются. Тестовая цель `analyzer-test` не содержит весов, а рабочая цель
`analyzer` не содержит `pytest`, компиляторов и `curl`.

Во время работы Transformers загружает модель только из
`/opt/models/ner_rus_bert-secret_detection` с отключённым сетевым поиском. Если
файлы отсутствуют, повреждены или не соответствуют ожидаемым меткам, Analyzer
не запускается. Источники, граница заимствования, проверка целостности и порядок
обновления описаны в
[документе о происхождении модели](research/ner-model-provenance.md).

| `OIDC_JWT` | Нет | JWT-токен доступа | Пользовательский OIDC/JWT-токен для примера корпоративной JWT-аутентификации. |
| `ANTHROPIC_BASE_URL` | Нет | HTTP/HTTPS URL | Базовый URL Claude Code или клиента, совместимого с Anthropic Messages API, при работе через прокси. |
| `ANTHROPIC_AUTH_TOKEN` | Нет | Токен авторизации Claude Code | В режиме, где Anthropic оплачивает и вызывает прокси, может быть пользовательским ключом прокси; в режиме сквозной передачи подписки не должен подменять локальную авторизацию Claude. |
| `ANTHROPIC_MODEL` | Нет | Имя модели LiteLLM | Модель, которую Claude Code должен вызывать через прокси, например `anthropic-example-standard`. |
| `ANTHROPIC_CUSTOM_HEADERS` | Нет | Строка заголовков | Для сквозной передачи подписки Claude может передавать `x-litellm-api-key: Bearer <proxy-token>`, пока авторизация Claude управляется клиентом. |

Эти переменные читает `scripts/create_virtual_key.sh` и цель Makefile `make virtual-key-create`. Для регулярного администрирования пользователей предпочтительнее административный интерфейс LiteLLM; вспомогательный сценарий нужен для CI, сквозных проверок и первичной настройки.

| `MODELS` | `standard` | Имена моделей или группы доступа через запятую | Список доступных моделей или групп доступа для пользовательского ключа. |

| `MAX_BUDGET` | Пусто | Число | Максимальный бюджет пользовательского ключа. |
| `RPM_LIMIT` | Пусто | Целое число | Ограничение запросов в минуту. |
| `TPM_LIMIT` | Пусто | Целое число | Ограничение токенов в минуту. |
