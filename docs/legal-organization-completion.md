# Завершение частичной маски организации с явной юрформой

> Историческое описание предыдущего варианта. В этой копии применяется
> [критерий названия](organization-identity-policy.md): новая граница не добавляет
> маску на ранее нераспознанную публичную юрформу. Старые цифры ниже сохранены
> как история, а не новая оценка.

Ограниченный локальный кандидат поверх исправлений Messages/tool choice.
Модель, пороги, словарь, planner окон и реализация кэша не меняются.

Для уже принятой NER-находки используется существующая ограниченная грамматика:
ООО/АО/ПАО/ОАО/ЗАО и два-три кириллических слова названия с заглавной буквы,
всего до128 символов. Конец подтверждается физическим концом строки/документа
с необязательной точкой или концом реального строкового литерала.

Завершение разрешено, если NER приняла всю юрформу и часть названия, либо
все буквы названия при явно написанной юрформе. Одна юрформа, пустой вывод,
слабая находка, неподтверждённый конец, конкурирующее чувствительное значение
и существующий boundary container не дают такого разрешения. Только label
«Организация» без юрформы также недостаточен.

Весь диапазон старых фрагментов входит в итоговую маску; confidence не повышается.
Если запрос исключает ORGANIZATION, новый путь не меняет PERSON-only результаты.
Внутренний provenance-флаг отличает достроенный диапазон от сырых предсказаний.
Подтверждённая граница защищена от последующей склейки с отдельной организацией
на следующей строке. Существующие legacy-склейки сохраняются: завершение не
используется, если его новая граница открыла бы уже защищённый separator.

Проверка:197 входов/1184 исхода каждого варианта. ORG-gold:117→130 полных,
63→50 частичных,81 полностью открытое наблюдение без изменений. Ни один прежний
masked char не открыт; новых масок в обычных контролях нет, статусы не изменились.
Суммарная вариативность масок выросла на7 символов: это новые защищённые части,
которые ранее оставались открыты во всех фазах. Строгий критерий стабильности
пока не выполнен. Полного решения распознавания/окон и production-readiness нет.

Тесты окончательного кода:91 новых,750 seeded iterations; полный Analyzer
3619 passed/1 прежний fail глубины JSON на Python3.12. Некэшированный реальный
Analyzer через Messages HTTP route подтверждает маску20/20 вместо9/20,
text/tool-input roundtrip и очистку mapping. Provider/Redis в стенде подставные.
Полностью ненайденные компании, quoted/Latin/односоставные и более длинные имена
этим ограниченным правилом не объявляются исправленными.
