# GPU-профиль Analyzer

Отчёт фиксирует проверку задачи #71 на одном сервере Ubuntu 24.04 `x86_64`:
8 vCPU, 31 GB RAM и NVIDIA Tesla T4 16 GB (compute capability 7.5). Использованы
драйвер 595.71.05, NVIDIA Container Toolkit 1.20.0, PyTorch 2.13.0 и CUDA 12.6.
Для CUDA 12.6 зафиксирован минимальный драйвер Linux 560.28.03.

## Итоговый профиль

- стандартный профиль остаётся процессорным;
- GPU-профиль выбирается через `ANALYZER_PROFILE=gpu`;
- один процесс Analyzer использует `cuda:0`, FP16 и пакет из восьми BERT-окон;
- параллельность внутри процесса равна одному; нагрузка масштабируется репликами;
- отсутствие CUDA, неподдерживаемая compute capability, ошибка прогрева или OOM
  приводят к явному нездоровому состоянию без перехода на CPU.

Логический размер CPU-образа составил 1,04 GiB, GPU-образа — 4,19 GiB. CUDA-
зависимости не попали в CPU-образ.

Три холодных запуска уже собранного GPU-образа достигли `ner_state=ready` за
9,133, 8,951 и 9,113 с; медиана — 9,113 с.

## Скорость

Медиана трёх прогретых запусков одного процесса на том же сервере:

| Условные токены | CPU FP32, с | GPU FP32, с | GPU FP16, с | Ускорение FP16 |
| ---: | ---: | ---: | ---: | ---: |
| 1k | 1,009 | 0,442 | 0,380 | 2,66× |
| 8k | 7,781 | 4,410 | 4,104 | 1,90× |
| 50k | 47,934 | 25,110 | 23,131 | 2,07× |
| 128k | 114,140 | 54,939 | 49,135 | 2,32× |

На 50k пакет 8 дал 19,067 с против 23,131 с при пакете 4. Пакеты 16 и 32
дали 19,199 и 19,195 с, поэтому дальнейшее увеличение не оправдано.

Параллельность 2 и 4 внутри одного процесса ухудшила и задержку, и суммарную
пропускную способность. На входе 1k один последовательный процесс дал 2,66 RPS,
два одновременных запроса — 2,25 RPS, четыре — 1,38 RPS.

Один вход 1m успешно обработан за 577,90 с против примерно 964–1034 с в прежних
CPU-измерениях. Это функциональная поддержка размера, а не интерактивный режим.
На таком входе NER заняла 32,28 с, а стадия Presidio — 274,81 с: после переноса
BERT на GPU существенная часть времени остаётся на CPU.

## Качество

CPU FP32, GPU FP32 и GPU FP16 дали одинаковые результаты на полном корпусе:

| Показатель | Значение |
| --- | ---: |
| F1 | 0,906 |
| Полнота маскирования | 0,970 |
| Покрытие критических примеров | 1,000 |

Типы, границы и решения о маскировании совпали. FP16 принят как рабочий режим.

## Нагрузка и устойчивость

- быстрая сквозная проверка: 143 запроса, 0 ошибок, 4,82 RPS;
- всплеск 400 запросов с одной репликой: 47 успешных ответов и 353 управляемых
  `503 analyzer_overloaded`; провайдер получил только 47 маскированных запросов;
- две GPU-реплики под непрерывной нагрузкой пережили остановку одной из них:
  один `503 analyzer_unavailable`, восстановление всех восьми пользователей за
  1–2 секунды, утечек исходных значений и остаточных таблиц замен нет;
- четыре реплики поместились на одной T4, но синхронный сквозной всплеск на
  восьмиядерном узле перегрузил весь контур. Этот опыт не используется как
  измерение ёмкости GPU.

Прямой параллельный тест отделил GPU от LiteLLM и балансировщика. Две реплики по
4 vCPU на одной T4 дали суммарно 5,06 RPS, четыре реплики по 2 vCPU — 10,66 RPS.
Каждая копия модели использовала около 932 MiB VRAM. Для входа 1k совместное
размещение четырёх реплик на T4 допустимо; большие поля требуют отдельной
проверки на целевом профиле трафика.

## Расчёт ресурсов

Для 400 пользователей исходная верхняя оценка — 26,7 полностью холодного ввода
1k в секунду. При ёмкости одной реплики `Cgpu = 2,663 RPS` и запасе 30%:

```text
ceil(26,7 × 1,3 / 2,663) = 14 реплик Analyzer
ceil(14 / 4) = 4 Tesla T4
```

Четыре T4 — консервативный ориентир для худшего случая, а не обязательный
начальный размер. Если холодный ввод не превышает 16,4 RPS, две T4 с восемью
репликами сохраняют тот же 30-процентный запас. Итоговое число определяется по
производственным метрикам промахов кэша, размера новых полей и BERT-окон.

Для промышленного контура следует начинать минимум с двух GPU-узлов, размещать
до четырёх процессов Analyzer на T4 и оставлять не меньше двух vCPU на процесс
для короткого ввода. Профиль больших полей требует больше CPU. Перед вводом в
эксплуатацию расчёт необходимо подтвердить распределёнными тестами задачи #59;
одна T4 не обеспечивает отказоустойчивость.

## Вывод

Недорогая Tesla T4 достаточна для текущей модели и даёт ускорение примерно
1,9–2,7 раза без потери качества. Более дорогая H200 не устранит CPU-часть
Presidio и не обоснована текущими измерениями. Следующий прирост следует искать
в оптимизации CPU-стадий и горизонтальном масштабировании, а не только в замене
видеокарты.

Версии сверены с [инструкциями PyTorch](https://pytorch.org/get-started/previous-versions/),
минимальный драйвер — с
[примечаниями NVIDIA к CUDA 12.6](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-toolkit-release-notes/index.html).
