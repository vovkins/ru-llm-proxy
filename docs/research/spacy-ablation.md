# Эксперимент исключения spaCy

Задача #94, PR #95. Исходная версия — `f8a5a01`: PERSON и ORGANIZATION уже
переданы специализированной BERT. Эксперимент не меняет рабочую конфигурацию,
пороги, веса модели и следующие этапы задачи.

## Вывод

Простая замена языковой обработки на `NoOpNlpEngine` неприемлема: теряется
контекстное усиление правил Presidio и возникают новые пропуски чувствительных
значений. Существующие NER-корпуса сами по себе эту регрессию не обнаруживают.
Рабочий вариант оставлен без изменений; постоянное удаление spaCy не выполнено.

## Методика

Три временные копии Analyzer проверяются последовательно:

- А: текущая конфигурация.
- Б: `nlp_engine.nlp["ru"].disable_pipe("ner")`; токенизация и лемматизация сохранены.
- В: штатный `NoOpNlpEngine` с языком `ru`, без внешней языковой модели.

Для В только инициализация NLP заменена на:

```python
nlp_engine = NoOpNlpEngine(models=[{"lang_code": "ru", "model_name": ""}])
nlp_engine.load()
analyzer = AnalyzerEngine(nlp_engine=nlp_engine)
```

Docker ARM64, 4 CPU / 4 GiB на испытуемый контейнер, `OMP_NUM_THREADS=4`,
`MKL_NUM_THREADS=4`, один исполнитель. Очередь в нагрузочном эксперименте
ожидает до 120 секунд; рабочие настройки не изменены. Presidio 2.2.364,
spaCy 3.8.16, `ru_core_news_sm` 3.8.0, PyTorch 2.13.0+cpu, Transformers 4.57.6.
Ревизия BERT — `52b5b0745aac14f73fcf2ac0f91d9b5001a85ae4`.

## Качество

Оба исходных корпуса и их ожидания сохранены. Дополнительные 51 примера
содержат 38 чувствительных значений и 13 отрицательных проверок конкретного
типа; представлены все 29 публичных категорий. Тип и полное покрытие значения
оцениваются отдельно, частичный результат не считается защитой всего значения.

| Проверка | А | Б | В |
| --- | ---: | ---: | ---: |
| Покрытие маскированием, исходные 77 примеров | 66/67 | 66/67 | 66/67 |
| Критическое покрытие исходного корпуса | 17/17 | 17/17 | 17/17 |
| Чувствительные значения в 43 примерах инструкций | 15/15 | 15/15 | 15/15 |
| Дополнительные значения, полное маскирование | 36/38 | 36/38 | 28/38 |
| Дополнительные значения, ожидаемый тип и полное покрытие | 34/38 | 34/38 | 26/38 |
| Отрицательные проверки конкретного типа | 13/13 | 13/13 | 13/13 |

Новые пропуски В: КПП с подписью, ИНН с подписью, БИК, два варианта адреса,
загранпаспорт, военный билет и свидетельство о рождении. Отсутствуют леммы
контекста, поэтому оценки правил остаются ниже порога 0.35. BERT их не заменяет.
Неизменные API-тесты В: 11 ошибок, 96 успешных проверок; одна ошибка относится
к контракту реестра, остальные — к обнаружению данных.

Исходные ограничения не скрыты: в А и Б не покрыты КПП после слова
«реквизиты» и отдельный десятизначный ИНН. В двух примерах значения защищены,
но специализированные правила возвращают AUTH_TOKEN вместо BEARER_TOKEN
и SECRET_KEY вместо API_KEY. Эти результаты не исправлялись ради эксперимента.

## Производительность

Размеры ниже — слова генератора, а не токены внешнего провайдера. В прогоне
1m BERT обработала 1 068 369 токенов и 3355 окон в обоих вариантах.

| Вход | А, секунды | Б, секунды | В, секунды | Повторы |
| --- | ---: | ---: | ---: | ---: |
| 8k | 6,52 | 7,18 | 7,06 | 3, медиана |
| 50k | 49,32 | 51,33 | 47,50 | 3, медиана |
| 128k | 118,12 | не запускался | 132,94 | 1 |
| 1m | 1141,08 | не запускался | 1061,85 | 1 |

Для 1m стадия Presidio сократилась с 136,56 до 11,96 секунды, а BERT заняла
1003,77 и 1048,92 секунды соответственно. Общее сокращение времени — около
7%, не кратное ускорение. Все четыре контрольных значения в начале, середине,
около границы окна и конце покрыты по точным координатам; следующий запрос
после большого входа успешен. Это функциональная проверка объёма, не SLA:
штатный тайм-аут защитного слоя по-прежнему равен 30 секундам.

Двадцать коротких запросов после длинной нагрузки дали p50/p95: А —
1,369/1,418 с, В — 1,285/1,313 с. В начальных сериях результаты отличались:
0,973/0,998 с и 1,158/1,358 с. Колебания BERT и порядок последовательных серий
не позволяют обещать устойчивое ускорение по одиночным длинным прогонам.

Пиковая рабочая память Docker для 1m: А — 1147 MB, В — 571 MB; сумма RSS —
1598 и 1010 MB. Это разные показатели, не объём выделенной памяти и не
универсальные требования к серверу. Пиковая загрузка CPU — 398,54% и 398,56%
по Docker, то есть почти четыре ядра в обоих вариантах. Очередь при двух клиентах также проверена;
повторные поля без кэша измерены на Analyzer отдельно от кэшируемой истории
в прокси. GPU и промышленная нагрузка в эксперимент не входят.

Через LiteLLM 1.98.0 с имитатором провайдера, Responses SSE, новый вход 1k
дал p50/p95 1,084/1,178 с для А и 1,058/1,126 с для В (20 запросов).
Для растущей истории 8k медианы трёх повторов — 6,909 и 6,032 с.
Закэшированное поле 1k заняло около 0,01 с: этот результат не считается
ускорением самого анализа. Все 52 запроса этих серий завершились успешно.

## Зависимости

Presidio 2.2.364 объявляет spaCy обязательной зависимостью. Даже `NoOpNlpEngine`
использует `spacy.tokens.Doc` и `spacy.vocab.Vocab`. Полное удаление пакета
поэтому не является поддерживаемой конфигурацией; платформенный код не патчился.

В сравнительных производных образах удалены `ru_core_news_sm` и её исключительные
зависимости `pymorphy3`, `pymorphy3-dicts-ru`, `dawg2-python`. По Docker API размер
уменьшился с 1 070 562 420 до 1 046 667 880 байт, примерно на 2,2%. Библиотека
spaCy и BERT остаются. Это одинаковые локальные пересборки уже установленных
зависимостей, не измерение полной сборки без кэша и повторного скачивания пакетов.
Без русской модели проходят `pip check`, запуск, прогрев BERT, длинный текст
и Unicode. Удаление spaCy в одноразовом контейнере приводит к
`ModuleNotFoundError` при импорте `presidio_analyzer`.

## Проверки и ограничения

Текущий код: 568 тестов Analyzer и 1043 проверки защитных обработчиков,
конфигурации и протоколов, всего 1611 уникальных проверок. Для А и В отдельно
пройдены по 43 проверки реальной BERT и 172 восстановления обоих API при
`stream=false/true` с имитатором провайдера. Они подтверждают
эти примеры, но не компенсируют восемь новых контекстных пропусков В. Аргументы
инструментов, границы событий и `encrypted_content` проверены существующей
матрицей и модульными тестами. Сигнатуры временных вариантов различаются;
проверка разделения кэша по сигнатуре пройдена. Основной Redis не очищался;
реальные внешние провайдеры и приложения Codex/OpenCode здесь не запускались.

Обнаружено отдельное ограничение текущей ветки: фильтр только PERSON,
ORGANIZATION или CONTRACT_NUMBER даёт HTTP 500, поскольку Presidio не находит
подходящего распознавателя и вызов внешней для его реестра BERT не выполняется.
Без NLP-распознавателя В аналогично ломается фильтр LOCATION. Это не означает
отсутствия детекции без фильтра; исправление нашего интеграционного кода требует
отдельного согласования. Рабочий стенд не менялся; временные контейнеры,
образы и сети удалены, общий кэш сборки не очищался.

## Воспроизведение качества

После запуска выбранной временной копии:

```bash
python -m presidio.evaluation.spacy_ablation \
  --analyzer-url http://127.0.0.1:17501 --variant c --output /tmp/quality-c.json
```

Параметр `--variant` — подпись результата, не настройка рабочего Analyzer.
Команда сохраняет диагностику, а не объявляет успешную приёмку. В отчёте нет
исходных текстов и значений; есть отпечатки корпусов, результаты по примерам
и сигнатура анализа. Производственные переменные и команды Make не добавлены.
