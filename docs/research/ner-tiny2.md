# NER-профиль `tiny2`: маленькая модель и постобработка границ

## Что это

Профиль `tiny2` заменяет BERT Никиты (`fef2/ner_rus_bert-secret_detection`,
178 млн параметров) на `cointegrated/rubert-tiny2` (29 млн), дообученную на тех же
восьми типах и 17 BIO-метках. Контракт Analyzer не меняется: та же архитектура
`BertForTokenClassification`, те же метки, окна по 384 токена, слияние с правилами,
формат ответа. Профиль по умолчанию — `bert`, его поведение не изменилось.

Выбор профиля — переменная `NER_MODEL_PROFILE` при сборке образа (она же задаёт
`PRESIDIO_ANALYZER_NER_MODEL_PROFILE` внутри образа). Как положить веса —
`presidio/model-artifacts/tiny2/README.md`.

## Что добавлено в обработку

В профиле `tiny2` два шага включены по умолчанию. Для `bert` оба выключены.

1. **Сдвиг порога** (`PRESIDIO_ANALYZER_NER_O_LOGIT_BIAS`, для `tiny2` — `1.0`).
   Перед выбором метки к логиту `O` («не сущность») прибавляется константа.
   Метку сущности модель ставит только при заметной уверенности; это снижает
   лишние срабатывания на обычном коде. Оценка `score` в ответе остаётся
   вероятностью модели для выбранной метки, фильтр `score_threshold` работает как
   прежде.
2. **Постобработка границ** (`PRESIDIO_ANALYZER_NER_SPAN_POSTPROCESSING`, для `tiny2`
   — `secrets-contracts`), модуль `presidio/ner/span_postprocessing.py`. Выполняется
   после сборки окон и до пересчёта координат в исходный текст:
   - соседние куски одного значения склеиваются, если между ними не больше двух
     символов и нет разделителя (пробел, кавычки, `= , ; ( ) [ ] { } < >`); тип берётся
     от самого длинного куска, оценка — минимальная;
   - учётные данные расширяются до ближайшего разделителя, включая `: @ / & ?`
     (чтобы в `scheme://login:password@host` получились два значения);
   - номера договоров расширяются без `: @ / & ?` (`/` — часть номера `2020/АГ/6581`);
   - с конца срезается `. , ; : ! ?`, если за знаком пробел или конец текста.

   Режим `secrets` делает то же только для учётных данных.

Tiny2 обычно находит секрет, но выделяет его кусками или не целиком. Без этих шагов
открытые куски значения уходили бы во внешнюю LLM.

## Как выбирались модель и настройки

- Обучающие данные пересобраны кодом пайплайна Никиты на CodeChat. Все диалоги
  его test исключены.
- Выбор checkpoint, режима постобработки и сдвига порога в финальной серии
  делался по validation до её тестового прогона. Ранее test Никиты уже
  неоднократно использовался для диагностики, поэтому он не служит закрытой
  приёмочной выборкой.
- Шесть обученных моделей (2 рецепта × 3 seed) дают на test 78,0–78,4% macro F1;
  одна — 75,0%.

## Проверка в сервисе

Те же 5 788 строк прогнаны через `HuggingFaceNERRecognizer.analyze()` из этого кода
(порог `score_threshold=0.35`, как в запросах защитного слоя; только NER, без правил),
CPU Mac M4 Pro, 8 потоков, по одной строке:

| Прогон | Macro F1 | Без AUTH_TOKEN | Лишние срабатывания | Время на 5 788 строк |
|---|---:|---:|---:|---:|
| `bert`, исходный код | 70,32 | 80,25 | 32 | 365 с |
| `bert`, новый код (по умолчанию) | 70,32 | 80,25 | 32 | 311 с |
| `bert` + сдвиг 1,0 + `secrets` | 73,87 | 84,20 | 21 | 309 с |
| `tiny2` без сдвига и постобработки | 55,43 | 61,21 | 92 | 31 с |
| `tiny2` (профиль по умолчанию) | **78,25** | 79,46 | 69 | **31 с** |

- С профилем `bert` по умолчанию ответы нового кода побайтно совпадают с ответами
  исходного кода на всех 5 788 строках.
- Цифры `tiny2` через сервис совпадают с офлайн-оценкой. Значит, нарезка окон
  Analyzer, порог 0,35 и нормализация текста не меняют результат.
- Путь NER в сервисе у `tiny2` примерно в 10 раз быстрее, чем у `bert`.

## Ограничения

- По PASSWORD, SECRET_KEY и ORGANIZATION BERT точнее, лишних срабатываний у tiny2
  примерно в три раза больше. Допустимая просадка должна быть согласована до
  включения.
- Test Никиты многократно использовался в исследовании; нужна проверка на
  реальном трафике, в том числе доли скрываемого текста (расширение границ может
  захватывать лишнее).
- Скорость мерилась на Mac, а не на целевом сервере и не во всём сервисе.
