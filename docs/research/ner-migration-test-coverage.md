# Покрытие миграции NER проверками

## Назначение

Документ фиксирует проверяемые свойства миграции Analyzer на модель
`fef2/ner_rus_bert-secret_detection` и связывает их с автоматическими
проверками. Матрица нужна для принятия решения по задаче #67: успешный запуск
одного тестового набора не должен подменять проверку качества модели,
корректности интеграции и невозможности передачи чувствительных данных
провайдеру.

Проверки используют только синтетические и обезличенные значения. Действующие
учётные данные и производственные тексты в тестовый набор не входят.

## Контуры запуска

### Быстрый обязательный контур

`make test-static`, `make test-recognizers`, `make test-guardrail` и
`make test-flow` проверяют код, контракты конфигурации и основные сценарии без
обращения к внешнему поставщику модели. Процесс GitHub Actions `Baseline CI` выполняет
доступную без тяжёлого образа часть при каждом изменении соответствующего кода.

### Контур с настоящей моделью

`make test-ner-integration` последовательно:

1. собирает производственный образ Analyzer с закреплённой моделью;
2. запускает `real_model_smoke.py` с `--network none`;
3. поднимает LiteLLM, настоящий Analyzer, Redis и тестовый провайдер;
4. проверяет режимы маскирования и блокировки для всех восьми типов;
5. подтверждает отсутствие исходных значений в запросе к провайдеру;
6. проверяет 43 примера инструкций (включая 14 контрольных), отсутствие
   ложного маскирования и полное покрытие чувствительных значений;
7. повторяет эти примеры через Chat Completions и Responses, в обычном и
   потоковом режимах, с точным восстановлением ответа тестового провайдера;
8. проверяет 36 примеров PERSON/ORGANIZATION, включая 10 контрольных,
   согласованность фильтров, 144 восстановления и 104 блокировки обоих API/режимов;
9. проверяет 32 парных контекстных примера (10 контрольных), 96 фильтров,
   128 восстановлений и 92 блокировки;
10. проверяет 12 прежних контрольных, теперь регрессионных примеров, 36 фильтров,
    48 восстановлений и 24 блокировки; разметка не меняется, лишней подписи нет.

В этом дополнительном корпусе контроль маскирования отделён от точности
классификации: неверный тип при полном покрытии значения остаётся ошибкой
качества и отражается в итоговых метриках. Обязательны покрытие одним целым
результатом и совпадение отдельных/совместных фильтров имён с полным анализом.
Критическое покрытие корпусов 36/32/12 составляет 6/6, 3/3 и 6/6.
В корпусах 36/32 остаётся неверный тип имени после неоднозначного слова «Клиент»;
пользователь принял его с оговоркой о пропуске при фильтре только PERSON.
Лишний PERSON на подписи `Ф.И.О. =` устранён без расширения правила на другие
окружающие фразы. Отдельный исследовательский контроль восьми новых примеров
показал неизменную неточность конечной точки инициала: точных совпадений 4/5,
критическое покрытие 80%, а не 100%. Пользователь принял это как пунктуационное
ограничение, сохранив требование защиты всех букв фамилии и инициалов. Разметка
не изменена; принятие ограничения не объявляет строгий контроль успешным.
[Подробности](ner-instruction-regressions.md#ограниченное-исправление-подписи-поля).
Исходный корпус из 77 примеров и исторические пороги не изменены.

Тестовый API контроля передачи опубликован только на `127.0.0.1:14012`.
При занятом порту переменная `NER_PROXY_CAPTURE_PORT` задаёт другой номер
порта (1–65535); она используется только сквозным тестом, не рабочим составом.

Процесс `NER model integration` использует кэш слоёв GitHub Actions, не требует
секретов поставщика и ограничен 45 минутами. Он запускается при изменении NER,
защитного обработчика или файлов собственного сквозного контура, а также вручную.

### Холодная проверка

Сборка без локального кэша, повторный запуск всего состава контейнеров и анализ
размера образа выполнены как отдельный заключительный этап задачи #67. Этот
этап не подменяется кэшируемым CI-контуром: он проверяет воспроизводимость с
чистого состояния. Условия, измерения и решение `GO` зафиксированы в
[`ner-migration-cold-validation.md`](ner-migration-cold-validation.md).

## Критерии успешности

- все быстрые тестовые наборы завершаются без ошибок;
- реальная модель успешно загружается и выполняет вывод без сети;
- Analyzer сообщает состояние `ready` только после прогрева;
- режим маскирования не передаёт провайдеру исходные значения и полностью
  восстанавливает тестовый ответ;
- режим блокировки возвращает безопасную ошибку до обращения к провайдеру;
- проверены все восемь типов сущностей из области миграции;
- тестовые журналы и отчёты не содержат исходных чувствительных значений;
- проверка качества корпуса остаётся выше согласованных порогов.

Для этапа 2 задачи #94 явно приняты два ограничения: неверный тип после
неоднозначного «Клиент» с пропуском при фильтре только PERSON и немаскируемая
конечная точка последнего инициала. Второе допустимо только при защите всех
букв фамилии и инициалов; другие пропуски и неточные границы этим решением
не разрешены. Строгие показатели продолжают публиковаться без изменения разметки.
