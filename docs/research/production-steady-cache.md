## Условия

Прежний сервер 32 vCPU / 62,79 GiB, неизменные 382 файла и образы.
24 Analyzer по 1 CPU / 2 GiB, 12 Triton по 2 CPU / 4 GiB, два LiteLLM.
Контроль A: C2/I2/B4, HTTP 20/10; кандидат B: C1/I4/B4, HTTP 20/10.
Один процесс Analyzer, очередь 32 / 45 с; внутренние очереди Triton прежние.
Настройки production и платформенный код не менялись.

Настоящие Analyzer/Tiny2 и тестовый провайдер; внешние LLM не вызывались.
Оба API с SSE, размеры 8k/32k/50k единиц генератора, не токенов LLM.
Подготовлены 64 ключа, по четыре независимых диалога; короткие серии
задействуют не весь пул. Внутри серии непрерывное независимое расписание,
без ожидания завершения предыдущей группы. Одновременно не более
96 запросов / 4 млн единиц / 64 MiB активных данных. Пропуски учитываются.
Каждая ступень длится четыре минуты плюс завершение начатых запросов.
Кэш очищается только перед независимой серией, не внутри неё.

## Кэш И Стоимость Заполнения

17/17 точечных запросов успешны. Точное повторение и другая реплика
дают попадание без новых окон NER; изменение символа, ключа или модели —
промах. Четыре параллельных диалога одним ключом восстановлены правильно.

Глобальное объединение запросов между процессами не предполагается.
В девяти проверенных значениях кэша исходный текст не обнаружен.

Заполнение H потребовало 872 отдельных запроса и 1858,68 с со всей

Всего заполнение: 935/936 успехов, 24 794 496 токенов / 78 228 окон NER.
Частичная подготовка M не включена в 1858,68 с; её клиентские времена

Затраты заполнения не входят в скорость горячей серии и не считаются нулевыми.

## Причина Остановки

В группе `prefill-steady-screen-A-M-0.5-r0-3` один из 16 запросов
получил 503 через 3,384 с: `phase=windowing`,
`failure_class=window_boundary_unresolved`, `Retry-After: 1`.
Это история инструмента с UTF-8 JSON, четыре поля, 24002 единицы при
заполнении номинальной истории 32k. Пока не установлено, какое поле
вызвало отказ и воспроизводится ли он без конкуренции.

Обнаружен новый случай ранее известного класса: нельзя безопасно
разрешить границу распознанной сущности. Это не `queue_timeout`
или `queue_limit`; увеличение очереди не является доказанным исправлением.
Остальные 15 запросов группы корректны, исходных маркеров у провайдера
и целевых ошибок Nginx нет. Полностью заполненный кэш не объявлялся:
контроллер остановился. Исключения, повторы и ослабление защиты не добавлены.
Одинаковое общее сообщение о недоступности guardrail может скрывать разные
причины 503; для промышленного стенда нужен именно класс отказа.

Последующая [диагностика 12 вызовами](ner-window-boundary-diagnostic.md)
воспроизвела отказ без конкуренции и установила неверное условие принятия
расширенных границ в нашем NER-коде. Согласованное исправление проверено отдельно
на 16 сквозных запросах; после отдельного согласования тестовых ожиданий
все 3180 Analyzer-тестов прошли. Приёмка исправления завершена, не нагрузочной ёмкости.

Пик суммы памяти контейнеров по выборкам 21,12 GiB, минимум доступной
RAM 39,19 GiB. OOM и перезапусков нет. 1614 выборок; все 62172 строки
содержат `memory.stat`. В сериях два пропуска из 16440 опросов очередей,
не принятые за нули. Пики CPU — интервальные средние, память реплик
снимается последовательно, неснятые короткие пики неизвестны.

145 частных регрессий прошли локально и на Linux; 804 статические,
32 проверки Make и 869 защитной обработки локально успешны.
Наборы пересекаются. 382 файла и прежние результаты неизменны.
Все 38 вычислительных контейнеров испытаний остановлены с кодом 0;
БД, Redis и данные сохранены. Основной локальный стенд 8/8 healthy.
Частный архив не содержит `.env`, `auth.json` и состояния с ключами.

Ограниченная диагностика и согласованное исправление впоследствии выполнены;
их результаты приведены выше. Продолжение измерений было отдельно согласовано:
оба варианта используют одну исправленную сборку. Новые короткие и четыре
длительных серии выполнены в отдельном составе; [их результаты](production-steady-cache-corrected.md)
не заменяют приведённые выше исходные данные. Ёмкость 400 пользователей
по этим испытаниям не подтверждена.
