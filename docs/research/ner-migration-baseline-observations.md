# Наблюдения при холодном запуске DeepPavlov

Этот документ дополняет [отчёт о качестве](ner-migration-baseline.md) и
фиксирует свойства текущего Analyzer, обнаруженные при воспроизводимом запуске
3 августа 2026 года. Это исходные наблюдения, а не результаты оптимизации.

## Сборка образа

- Образ собран на `arm64` из `python:3.11-slim` без кэша проекта.
- Архив `ner_rus_bert_torch_new.tar.gz` имеет размер `1 440 917 530` байт.
- Фактическая SHA-256 архива:
  `9b605512566cafc5ec24ec3269572ac8ff572c7ad32b54c9915ee7324f2796e3`.
- Текущий Dockerfile выводит контрольную сумму, но не требует её совпадения с
  ожидаемым значением по умолчанию.
- Итоговый локальный образ имеет размер `4 752 964 951` байт.
- Из-за диапазона `torch<3.0,>=2.0` была установлена версия `2.13.0` вместе с
  CUDA 13 и крупными пакетами NVIDIA, хотя контейнер работал только на CPU.
- Холодная сборка в данном окружении заняла около 25 минут. Значение зависит от
  сети и машины и не является производительным нормативом.

Оптимизация CPU/GPU-образов остаётся предметом задачи
[#62](https://github.com/vovkins/ru-llm-proxy/issues/62).

## Запуск контейнера

- Контейнер начал запуск в `12:06:09 UTC`, а Uvicorn сообщил о готовности в
  `12:12:15 UTC`: холодный старт занял приблизительно 365 секунд.
- До окончания загрузки модели HTTP-порт не принимал соединения, а Docker
  healthcheck перешёл из `starting` в `unhealthy`.
- Несмотря на наличие архива в образе и вызов DeepPavlov с `download=False`,
  Transformers обратился за базовыми артефактами
  `DeepPavlov/rubert-base-cased`.
- За время запуска наблюдалось около 708 МБ входящего сетевого трафика
  контейнера.
- После загрузки health API вернул `status=ok`, `ner=loaded`.

Следовательно, текущий образ не обеспечивает полностью автономный запуск. В
целевом состоянии #67 все необходимые файлы должны находиться в образе, а
загрузка выполняться с `local_files_only` и закреплённой ревизией.

## Длинные запросы

В корпусе есть два сценария с входом длиннее 512 токенов:

- `person_after_long_prefix`;
- `secret_key_long_context`.

Для обоих DeepPavlov записал ошибку:

```text
input sequence after bert tokenization shouldn't exceed 512 tokens
```

При этом `DeepPavlovRecognizer` подавил исключение, а Analyzer вернул HTTP 200 с
частичными результатами детерминированных распознавателей. Health остался
`loaded`, а счётчик отказов NER не изменился. Поэтому показатели покрытия в
основном отчёте для этих сценариев не означают, что NER отработал успешно.

Это подтверждает необходимость предусмотренных в #67 перекрывающихся окон и
отказа от молчаливого перехода на частичный результат при ошибке NER.
