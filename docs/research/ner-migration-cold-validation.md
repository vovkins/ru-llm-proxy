# Холодная проверка миграции NER

## Решение

**GO:** Analyzer готов к переходу с DeepPavlov на закреплённую модель
`fef2/ner_rus_bert-secret_detection`. Итоговая процессорная сборка, автономный
запуск, оценка качества, полный состав Docker Compose и связанные проверки
завершились успешно. Открытых блокирующих замечаний после повторного прогона нет.

Оптимизация процессорного образа из
[#62](https://github.com/vovkins/ru-llm-proxy/issues/62) выполнена в той же ветке.
Нагрузочное исследование [#55](https://github.com/vovkins/ru-llm-proxy/issues/55)
остаётся отдельной работой.

## Воспроизводимость

Проверка выполнена 5 августа 2026 года на Apple Silicon (`linux/arm64`):

- ревизия кода: `561fd2cb38667138db829341d2a5c712f5741395`;
- рабочее дерево при оценке модели: чистое;
- новый изолированный BuildKit без прежних слоёв и кэша пакетов;
- сборка с `--no-cache --pull` и загрузкой результата в Docker;
- модель `fef2/ner_rus_bert-secret_detection`, ревизия
  `52b5b0745aac14f73fcf2ac0f91d9b5001a85ae4`;
- SHA-256 весов
  `6a2c875d02398554ec69384f489a0bf4fe3505fc347c6cdd3385d4fd31ef21a4`;
- только искусственные служебные секреты, без действующих ключей и обращений к
  поставщикам моделей.

Команда холодной сборки:

```bash
docker buildx build \
  --builder ru-llm-proxy-cold-561fd2c \
  --no-cache --pull --load --target analyzer \
  --tag ru-llm-proxy-presidio-analyzer:cold-561fd2c \
  --file presidio/Dockerfile presidio
```

## Качество и сквозной поток

Обезличенный корпус из 77 примеров и 67 ожидаемых сущностей обработан без
ошибок. Покрытие критических значений равно 1,000, критических пропусков нет,
все согласованные пороги качества пройдены. Машиночитаемый результат находится
в [`huggingface-candidate.json`](../../presidio/evaluation/reports/huggingface-candidate.json),
а краткая интерпретация — в
[`ner-migration-candidate-observations.md`](ner-migration-candidate-observations.md).

Отдельно подтверждены:

- перекрывающиеся окна, повторная обработка спорной границы со смещением и
  сохранение исходных смещений в длинном тексте;
- локальный безопасный отказ только неразрешимого запроса без перевода исправной
  модели в состояние `failed`;
- маскирование, восстановление и блокировка всех восьми типов из области
  миграции через настоящий Analyzer и макет поставщика;
- отсутствие исходных чувствительных значений в переданном поставщику запросе;
- нулевое число обращений к поставщику в режиме блокировки.

## Полный состав решения

LiteLLM, Analyzer, PostgreSQL и Redis запущены с новым томом базы и искусственными
ключами. Проверены:

- готовность всех четырёх сервисов;
- регистрация обоих защитных слоёв и полного контракта из 29 типов сущностей в
  `/guardrails/list`;
- состояние Analyzer `ready` после прогрева;
- публичные метрики LiteLLM, защитного слоя и Analyzer;
- отсутствие необходимости обращаться к внешней модели для этих проверок.

промышленной среды.

## Ограничения

- проверка выполнена на одной ARM64-машине с Docker Desktop;
- конкурентная нагрузка и предельная пропускная способность не измерялись;
- производственные ключи и внешние модели намеренно не использовались;
- выполнение на видеокарте не поддерживается и не проверялось.

Эти ограничения не влияют на решение о корректности миграции. Нагрузочные
испытания выполняются отдельно в #55.

## Откат

Переключатель между двумя NER-моделями намеренно не поддерживается. Для отката
следует развернуть предыдущий неизменяемый выпуск целиком, затем проверить
`/api/v1/health` и основные режимы защитного обработчика. Старый Analyzer нельзя
смешивать с новым кодом слияния результатов и новым контрактом сущностей.
