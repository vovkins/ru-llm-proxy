# Локальная проверка маскирования 54 env-имён

Добавлен отдельный opt-in класс
`litellm_guardrails.env_assignment_masking.RuEnvAssignmentGuardrail`.
Основной `RuPIIGuardrail` и конфигурации по умолчанию не меняются.

Класс поддерживает фиксированные 54 имени из `MASKED_ENV_NAMES`; не добавляет
автоматически произвольные `*_TOKEN` или `*_PASSWORD`. Полный список находится
в модуле. Для включения в отдельном локальном экземпляре достаточно заменить
путь класса у pre-call guardrail на этот путь. Обычный post-call guardrail
совместим: используется тот же request-scoped mapping Redis, TTL и streaming.
Локальный экземпляр должен сохранять `pii_mode=mask`, `pre_egress_policy_mode=block`
и `final_payload_leak_check_mode=block`. Проверки не отключаются.

Пример непосредственного использования:

```python
from litellm_guardrails.env_assignment_masking import RuEnvAssignmentGuardrail

guardrail = RuEnvAssignmentGuardrail()
# Тот же async_pre_call_hook / async_post_call_success_hook, что у основного класса.
```

Примеры provider-bound текста:

```text
PWD=ENV_MASK_V1_1
JIRA_TOKEN="ENV_MASK_V1_2"
{"DB_PASS": "ENV_MASK_V1_3"}
```

Скрывается всё значение, имя и разделитель сохраняются. Путь от пароля по
виду строки не отличаем. Bare-плейсхолдеры состоят из букв/цифр/подчёркиваний,
поэтому сами по себе не превращают env-присваивание в shell-redirection.
Первая проверка работает с исходными признаками логов/конфигов/тем. Освобождение
от env-проверки относится только к сгенерированным в текущем запросе alias.
Входные alias в смешанном запросе не считаются доверенными. Запрос копируется;
исходное содержимое не изменяется при ошибке.

Поддерживаются однострочные env-присваивания, export, YAML scalar, env-list,
полный JSON-документ со строковыми значениями, кавычки и Windows-пути.
Для JSON сохраняется исходная лексическая запись (включая escape-последовательности).
Восстановление — точное для исходного текста; преобразование escape-последовательностей
при переносе моделью значения в другой язык/формат отдельно не проверено.

Многострочные YAML scalars, shell substitution/цепочки команд, ссылки `${...}`,
числовые JSON-поля и неразобранные записи по-прежнему могут возвращать 422.
Другие env-имена и другие pre-egress правила сохраняют прежнюю политику.
Ошибка сохранения mapping не допускает продолжения даже при `fail_open`.
Если известное замаскированное значение осталось открытым в комментарии или другом
provider-bound поле, запрос также отклоняется. Для полного JSON-документа проверяется
сохранность структуры, ключей и типов после Analyzer. Это консервативно: короткие
значения, совпавшие с другим обычным текстом, тоже могут сохранить блокировку.
Публичные URI из фиксированного списка тоже скрываются целиком — это сознательное
избыточное маскирование в локальном варианте.

Событие `env_assignment_masked` пишет только request ID, версию и количества.
Предварительные alias используют атомарное расширение словарных replacement spans
и тот же механизм хранения/восстановления. Поэтому общая audit-классификация
базового hook может учитывать их в dictionary mapping; отдельное событие отличает
эту обработку. Значения не включаются в журнал.

Тесты: `litellm_guardrails/tests/test_env_assignment_masking.py`.
Используются настоящие hooks и тестовые Analyzer/Redis; это не приёмка полного
production-маршрута. Реальный Analyzer, внешняя модель, DLP/VPN и выполнение
команд с восстановленными аргументами требуют отдельной проверки до внедрения.

В Responses-продолжениях диапазон ENV-alias выделяется после загрузки mapping
предыдущего ответа: новые значения не перезаписывают старые. Входные значения,
известные из этого mapping, также проверяются на открытые повторы.
