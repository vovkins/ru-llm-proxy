# Маски и разметка пронумерованного исходника

Подтверждённая PERSON-находка может включать перевод строки и номер следующей
строки. Восстановление ответа при этом остаётся точным, но модель получает
искажённый исходник. После обязательных проверок NER и объединения результатов
Analyzer исключает из таких масок только доказанную разметку отображения.

Правило применяется к raw text и только к PERSON из NER с признаком
подтверждённого boundary container либо PERSON control. Нужна последовательность
не менее двух пронумерованных строк, начинающаяся с `1:`. Открываются разделяющий
перенос строки, числовой префикс с двоеточием и отступом, а также двоеточие после
ограниченного поля. Буквы ключа поля остаются закрыты: ключ сам может быть именем.

Например, диапазон `Иван\n4: Петров` превращается в две отдельные маски:
`<PERSON_1>\n4: <PERSON_2>`. Обе части имени остаются скрыты. Все символы
исходной положительной находки, кроме подтверждённой разметки, сохраняют покрытие.

Любая независимая native-находка на предлагаемом разделителе запрещает его
исключение. Строковые литералы, fenced/inline code, ссылки и неизвестное владение
разметкой остаются непрозрачными. Находки остальных типов не изменяются.
Невалидная нумерация, одиночные строки и последовательность без начала `1:` не
дают исключения. JSON tool arguments с экранированным исходником этим правилом
не исправляются: их прежняя scalar-проекция остаётся отдельным механизмом.

Это исправление границ маски. Оно не меняет веса или пороги NER и не доказывает,
что техническое слово, ошибочно помеченное PERSON, стало правильно распознаваться.

Проверки включают пять видов переноса строки, разорванное настоящее имя,
оба служебных признака контейнера, независимые находки всех поддерживаемых типов,
неизменность чужих объектов, непрозрачные/незакрытые конструкции и отмену обработки.
