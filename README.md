# ru-llm-proxy 🛡️

Прокси на базе LiteLLM для безопасной работы с внешними языковыми моделями. Он
проверяет русскоязычные персональные данные и служебные секреты, после чего
маскирует их либо блокирует запрос до передачи провайдеру.

Ключи провайдеров остаются на сервере. Пользователи получают отдельные ключи
LiteLLM с назначенными моделями, бюджетами и ограничениями.

## Статус проекта

✅ В текущем `main` работают:

- OpenAI-совместимый шлюз и базовые текстовые запросы Anthropic Messages API;
- `glm-5.2` по умолчанию и дополнительное имя `glm-5.1`;
- пул из двух подписок Z.AI Coding Plan с закреплением клиентского ключа за
  выбранным провайдером модели;
- распознаватели на регулярных выражениях, spaCy и специализированная BERT-модель;
- маскирование, блокировка, восстановление ответа и временные сопоставления в Redis;
- предварительная и финальная проверки полезной нагрузки до вызова провайдера;
- Словарные подстановки для десяти крупных российских банков;
- Список разрешённых синтетических тестовых персональных данных;
- политика регулируемых тем;
- ограничение нагрузки Analyzer, безопасный отказ, HMAC-кэш анализа
  неизменившихся полей и переиспользуемые Redis/httpx-клиенты защитного обработчика;
- откалиброванные пороги русскоязычных распознавателей;
- базовые текстовые блоки `content` в Anthropic Messages;
- метрики Prometheus, журналы аудита, автоматические проверки и базовые проверки протоколов `/v1`.

⚠️ Основные ограничения:

- восстановление требует, чтобы модель вернула служебную метку без изменений;
- в потоковых ответах восстанавливаются `delta.content` и
  `delta.reasoning_content`, но не аргументы вызовов инструментов;
- поток Responses API с `response.output_text.delta` сейчас возвращает
  безопасную служебную метку без восстановления исходного значения;
- полноценный шлюз Claude Code пока не считается полностью проверенным;
- промышленный запуск в Kubernetes проектируется отдельно в issue #59.

## Что защищает прокси

- **Персональные и чувствительные данные:** телефоны, адреса электронной почты,
  ФИО, адреса, организации, локации, номера договоров, российские документы,
  реквизиты организаций, счетов и банковских карт.
- **Служебные секреты:** внутренние адреса и домены, URL с учётными данными,
  JWT, токены, приватные ключи, API-ключи, пары логин/пароль, конфигурации и
  журналы.

Для `RU_INN` действует отдельная политика. При
`PRESIDIO_ANALYZER_DETECT_BARE_INN_BY_CHECKSUM=true` 12-значный ИНН с корректной контрольной суммой
проходит `score_threshold=0.35` без контекста; 10-значный ИНН требует контекст.
Ограничения остальных сущностей описаны в
[архитектуре](docs/architecture.md).

## Быстрый старт

Требуются Docker с Compose, GNU Make и два ключа Z.AI Coding Plan.

```bash
git clone https://github.com/vovkins/ru-llm-proxy.git
cd ru-llm-proxy
make setup STACK=litellm-presidio
```

Укажите ключи в созданном `.env`:

```env
ZAI_API_KEY=your-zai-key
ZAI_API_KEY_2=your-second-zai-key
```

```bash
make build
make up STACK=litellm-presidio
make health STACK=litellm-presidio
```

Первая сборка скачивает `ru_core_news_sm` и закреплённую ревизию
`fef2/ner_rus_bert-secret_detection`; веса BERT занимают около 709 МБ. Во время
работы Analyzer читает модель из образа и не обращается к Hugging Face. Образ
использует процессорную сборку PyTorch; выполнение на видеокарте не поддерживается.

Расширенный состав добавляет пул ChatGPT OAuth-подписок через штатный
`codex-lb`, не меняя обычный запуск с GLM. Его порядок запуска и
администрирования описан в [руководстве по `codex-lb`](docs/codex-lb.md).

## Первый запрос

Создайте пользовательский ключ в административном интерфейсе LiteLLM или
локальной командой:

```bash
make virtual-key-create STACK=litellm-presidio \
  KEY_ALIAS=local-client MODELS=standard,zai DURATION=30d
```

```bash
curl http://localhost:4000/v1/chat/completions \
  -H "Authorization: Bearer $RU_LLM_PROXY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5.2",
    "messages": [
      {"role": "user", "content": "Клиент Иванов Иван, телефон +79031234567. Составь краткое резюме."}
    ]
  }'
```

`LITELLM_MASTER_KEY` предназначен только для администрирования. Не передавайте
его пользователям и клиентским приложениям. Дополнительные запросы приведены в
[примерах API](docs/examples.md).

## Режимы защиты

| Настройка | Назначение |
| --- | --- |
| `PII_GUARDRAIL_MODE=mask` | Маскировать найденные данные и восстанавливать их в ответе. |
| `PII_GUARDRAIL_MODE=block` | Останавливать запрос с персональными данными до вызова провайдера. |
| `PRE_EGRESS_POLICY_MODE=block` | Блокировать исходные конфигурации и журналы с кодом `pre_egress_policy_blocked`. |
| `FINAL_PAYLOAD_LEAK_CHECK_MODE=block` | Повторно проверять изменённую полезную нагрузку перед провайдером. |
| `REGULATED_TOPIC_POLICY_MODE=block` | Блокировать регулируемые темы с высокой уверенностью. |

По умолчанию инфраструктурные сбои обрабатываются безопасным отказом
(`PII_GUARDRAIL_FAILURE_MODE=fail_closed`). Перегрузка Analyzer
(`analyzer_overloaded`) блокирует запрос независимо от этой настройки.

## Основные команды

| Команда | Назначение |
| --- | --- |
| `make build` | Собрать и загрузить образы обоих составов. |
| `make setup STACK=litellm-presidio` | Настроить базовый состав. |
| `make setup STACK=litellm-presidio-codex-lb` | Настроить расширенный состав и служебный ключ `codex-lb`. |
| `make up STACK=<состав>` / `make down STACK=<состав>` | Запустить или остановить явно выбранный состав. |
| `make health STACK=<состав>` | Проверить все компоненты выбранного состава. |
| `make test` | Быстрый локальный набор: `test-unit` и `test-static`. |
| `make test-static` | Лёгкие статические и asyncio-регрессионные тесты на хосте через `PYTHON_LOCAL`. |
| `make test-recognizer-api` | Проверить Analyzer API и пороги распознавателей в Docker. |
| `make guardrails-smoke STACK=<состав>` | Проверить обычные и потоковые защитные слои запущенного состава. |
| `make test-e2e STACK=<состав>` | Выполнить запрос к реальному провайдеру. |

Полный список: `make help`. Полный порядок проверки перед выпуском версии:
[docs/compliance.md](docs/compliance.md).

Доказательные контуры запускаются отдельно: `make test-egress-security`
проверяет исходящую нагрузку, `make test-observability-gates` — телеметрию.

Эндпоинт LiteLLM `/metrics` открыт без ключа LiteLLM API и должен быть ограничен
на сетевом уровне. Настройка `require_auth_for_metrics_endpoint: false`, метрики и
рекомендуемые оповещения описаны в [docs/monitoring.md](docs/monitoring.md).
