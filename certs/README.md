# Корпоративный корневой сертификат (air-gapped среда)

Эта директория — единая точка для корневого сертификата корпоративного
перехватывающего (re-signing) прокси / DLP. Он нужен, чтобы исходящий TLS к
провайдерам и загрузки при сборке (apt, внутреннее PyPI-зеркало, spaCy,
DeepPavlov, HuggingFace) **доверяли** прокси, а не отключали проверку TLS
(`SSL_VERIFY=False`).

## Что положить

Поместите полную цепочку корневого CA (root + промежуточные) в один PEM-файл:

```
certs/proxy-ca.crt
```

Формат — PEM (текстовые блоки `-----BEGIN CERTIFICATE----- ... -----END CERTIFICATE-----`,
можно несколько подряд). Как получить файл — уточните у команды сетевой
безопасности; часто он лежит на прокси-хосте или выгружается из браузера при
просмотре перехватывающего сертификата.

Пример — сохранить сертификат корпоративного прокси через `openssl`:

```bash
openssl s_client -connect proxy.corp.example.com:443 \
  -showcerts </dev/null 2>/dev/null \
  | openssl x509 -outform PEM > certs/proxy-ca.crt
```

Если прокси отдаёт цепочку из нескольких сертификатов, сохраните все блоки
`-----BEGIN CERTIFICATE-----` … `-----END CERTIFICATE-----` в один файл.

## Как это используется

- `presidio/Dockerfile` копирует `certs/proxy-ca.crt` в системный trust store
  (`update-ca-certificates`) и дописывает его в `certifi`, чтобы apt/pip/urllib/
  requests/httpx/huggingface доверяли прокси при сборке и в рантайме.
- `litellm/Dockerfile` дописывает сертификат в `certifi` внутри venv LiteLLM
  (`/app/.venv`), который используется для исходящих вызовов к провайдерам.

Оба Dockerfile копируют **всю** директорию `certs/` и устанавливают сертификат
только если `*.crt` присутствует. Поэтому **без** `proxy-ca.crt** образы всё равно
собираются (обычный интернет, доверие через стоковый `certifi`/системные CA).

## Безопасность

- `certs/*.crt` (и `*.pem`, `*.key`) — в `.gitignore`. **Никогда не коммитьте**
  корпоративный сертификат в репозиторий.
- В трекинге остаётся только этот `README.md`.
