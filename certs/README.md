# Корпоративный корневой сертификат

Для работы через корпоративный прокси, который переподписывает TLS-соединения,
поместите согласованные корневые и промежуточные сертификаты в один или
несколько файлов верхнего уровня:

```text
certs/proxy-ca.crt
certs/proxy-intermediate-ca.crt
```

Каждый файл `certs/*.crt` должен быть в формате PEM и может содержать несколько
блоков `BEGIN CERTIFICATE`. Получите цепочку у команды сетевой безопасности, не
выгружайте ее с непроверенного узла. Во время сборки блоки нормализуются и
проверяются; поврежденный PEM останавливает сборку.

Во время сборки сертификат добавляется:

- в системные хранилища доверия образов LiteLLM, Analyzer и тестов;
- в `certifi` внутри среды LiteLLM;
- в дополнительное хранилище Node.js внутри образа LiteLLM.

Проверка TLS остается включенной. Использовать `SSL_VERIFY=False` или похожие
обходы не требуется.

Docker передает в контекст сборки всю директорию `certs/`, хотя обработчик
доверия использует только верхнеуровневые `*.crt`. Перед сборкой оператор обязан
проверить все содержимое директории и удалить материалы, которые не должны
попасть в слои образов. Файлы `certs/*.crt`, `certs/*.pem` и `certs/*.key`
исключены из Git; в репозитории хранится только эта инструкция.
