# Оценка качества NER

Этот каталог содержит воспроизводимую проверку качества для миграции NER из
задачи [#67](https://github.com/vovkins/ru-llm-proxy/issues/67).

## Состав

- `data/ner_migration.jsonl` — обезличенный корпус;
- `corpus.py` — разбор разметки и проверка схемы;
- `metrics.py` — расчёт точных совпадений и покрытия для маскирования;
- `run_baseline.py` — запуск корпуса через работающий Analyzer;
- `reports/deeppavlov-baseline.json` — неизменяемые исходные показатели старой модели;
- `docs/research/ner-migration-baseline.md` — исторический сводный отчёт;
- `reports/huggingface-candidate.json` — результат текущей модели;
- `docs/research/ner-migration-candidate.md` — сводный отчёт текущей модели;
- `docs/research/ner-migration-candidate-observations.md` — сравнение и выводы.

Отдельные артефакты проверки детерминированного слоя из репозитория модели:

- `deterministic_rule_source_manifest.json` — закреплённые исходники, контрольные суммы и лицензии;
- `data/deterministic_rules_review.jsonl` — обезличенные примеры правил и ложных срабатываний;
- `review_deterministic_rules.py` — изолированный прогон после проверки исходников;
- `reports/deterministic-rule-review.json` — показатели по каждой семье правил;
- `reports/deterministic-rule-inventory.json` — решение по каждому из 222 правил без копирования выражений;
- `docs/research/ner-deterministic-rule-review.md` — выводы и принятый набор правил.

Корпус не содержит производственные запросы, реальные персональные данные или
действующие ключи. Все похожие на учётные данные значения синтетические.

## Формат корпуса

Каждая строка — отдельный JSON-объект. Ожидаемые сущности размечаются внутри
текста:

```json
{"id":"person_full_name_ru","annotated_text":"Клиент {{PERSON:Иван Сергеевич Петров}} подтвердил заявку.","critical":true,"tags":["positive","person","ru"]}
```

Перед отправкой в Analyzer маркеры удаляются, а границы рассчитываются в
символах исходной строки Python. Это важно для составных символов Unicode и
эмодзи.

Обязательные свойства записи:

- стабильный `id` в нижнем регистре;
- непустой `annotated_text`;
- ровно одна метка `positive` или `negative`;
- только поддерживаемые целевые типы;
- `critical=true` только для положительных примеров.

Поля `prefix_repeat` и `suffix_repeat` позволяют воспроизводимо создавать
длинные примеры без копирования больших фрагментов в файл.

## Показатели

- **Точное совпадение** — совпали тип, начало и конец.
- **Покрытие правильным типом** — результат того же типа полностью закрывает
  ожидаемое значение, но может иметь более широкие границы.
- **Покрытие для маскирования** — ожидаемое значение полностью закрыто любым
  результатом Analyzer. Показатель отражает защиту от передачи значения, но не
  подтверждает правильную классификацию.
- **Критическое покрытие** — покрытие примеров с `critical=true`.

Отчёты содержат идентификаторы примеров, типы и агрегаты, но не содержат
исходный текст или найденные значения.

В отчёте сохраняются SHA-256 корпуса, ревизия `HEAD` и признак наличия
незакоммиченных изменений на момент запуска. Промежуточный прогон из рабочего
дерева поэтому нельзя ошибочно принять за результат указанного чистого коммита.
Итоговый прогон запускается только из чистого рабочего дерева с доступной
ревизией Git; при нарушении этого условия команда завершается до обращения к
Analyzer.

## Запуск

Быстрые тесты не загружают модель:

```bash
make test-ner-evaluation
```

Для полного прогона Analyzer должен работать локально и сообщать
`ner=loaded`:

```bash
make ner-evaluate
```

Команда записывает отчёты даже при нарушении порога, но завершается ненулевым
кодом, если критическое покрытие ниже 100%, точность или полнота `LOGIN`,
`PASSWORD`, `AUTH_TOKEN`, `SECRET_KEY`, `CONTRACT_NUMBER` ниже 95% либо полнота
`PERSON`, `LOCATION`, `ORGANIZATION` упала более чем на два процентных пункта
относительно сохранённого исходного отчёта DeepPavlov.

Другой адрес можно передать явно:

```bash
make ner-evaluate ANALYZER_URL=http://analyzer.example:5001
```

Для локального Docker-запуска команда также записывает версии основных пакетов
из контейнера `presidio-analyzer`. При удалённом Analyzer это можно отключить:

```bash
make ner-evaluate ANALYZER_URL=http://analyzer.example:5001 NER_EVALUATION_RUNTIME_CONTAINER=
```

Команда по умолчанию записывает в отчёт закреплённую контрольную сумму файла
весов. Другой исследовательский артефакт можно указать явно:

```bash
make ner-evaluate NER_EVALUATION_MODEL_SHA256=<sha256-файла-весов>
```

Флаги `--allow-degraded` и `--allow-case-errors` предназначены только для
диагностики. Второй флаг позволяет записать отчёт с идентификаторами примеров,
которые Analyzer не смог обработать, но не раскрывает их содержимое. Без этого
флага наличие хотя бы одной ошибки завершает команду ненулевым кодом.

```bash
make ner-evaluate NER_EVALUATION_FLAGS=--allow-case-errors
```

Для локальной диагностики из рабочего дерева с незакоммиченными изменениями
нужно явно передать `NER_EVALUATION_FLAGS=--allow-dirty-worktree`. Такой отчёт
сохраняет `git_worktree_dirty=true` и не должен публиковаться как итоговый.

Проверяемый отчёт формируется в два коммита: сначала фиксируется оцениваемый
код, затем из этого чистого коммита выполняется прогон и отдельным следующим
коммитом сохраняются сформированные JSON и Markdown. Поэтому указанная в отчёте
ревизия является родительской для коммита с самим отчётом.

Исторические файлы `deeppavlov-baseline.json` и
`ner-migration-baseline.md` не должны перезаписываться текущими прогонами.

## Проверка детерминированных правил

Для этой проверки не нужны веса модели. Нужны только текстовые файлы
репозитория модели на ревизии, указанной в
`deterministic_rule_source_manifest.json`. Исходники хранятся вне проекта и
перед исполнением проверяются по SHA-256.

В окружении тестового образа Analyzer выполните:

```bash
python3 presidio/evaluation/review_deterministic_rules.py \
  --source-dir /path/to/verified-model-source
```

Скрипт не меняет активные распознаватели. Он обновляет только исследовательский
отчёт и поштучный реестр. Согласованный по итогам исследования набор реализован
отдельно в `presidio/recognizers/credential_rules.py`; соответствие списка из
23 правил реестру проверяется автоматическим тестом. Остальные правила нельзя
переносить без нового поштучного согласования.
